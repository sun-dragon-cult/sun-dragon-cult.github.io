The RQG system has an API that macros and modules can use to roll dice, cast spells and read
information about characters. It's available in Foundry as `game.system.api`.

If you write macros to automate things at your table, or build a module that works with RQG, the API
has two parts:

- **The character data**, `actor.system` and `item.system`. Read values that are stored on a
  character, like characteristics, hit points or a cult's Rune Points, straight from there, and
  change them with Foundry's `actor.update` and `item.update`. See
  [Values stored on the character](/rqg-system/api/character-data#values-stored-on-the-character).
- **`game.system.api`**, for everything that needs the rules, like rolling dice and casting spells.

Modules can also call the [roll methods](/rqg-system/api/rolls#rolling-from-an-actor-or-item) on
RQG's actors and items, and `actor.damage`, `actor.heal` and `actor.getCastableSpells`. Don't call
other methods on them or use other parts of the system directly. Those can change in any release.

## What's in it

- [Rolls](/rqg-system/api/rolls) – roll skills, runes, passions and characteristics, attack with
  weapons and cast spirit and rune magic.
- [Roll hooks](/rqg-system/api/hooks) – react to rolls, add modifiers, or forbid a parry or dodge.
- [Character data](/rqg-system/api/character-data) – read skills, castable spells, hit points, magic
  points, rune points and other values from a character.
- [Behaviors](/rqg-system/api/behaviors) – make a spell or skill do something when Apply is clicked,
  like Dispel Magic removing spells or First Aid healing a wound.
- [Macro examples](/rqg-system/api/macro-examples) – ready-to-use macros to start from.
- [RQG System ID (rqid)](/rqg-system/api/rqid) – find the best version of a document by its RQG id.

## Pointing at actors and items

Wherever the API needs an **actor** you can give it an actor, a token, or the name, id or uuid of
one. If you leave the actor out, the first selected token is used, or else your assigned character.

Wherever it needs an **item** you can give it the item itself, or its name, id, uuid or rqid. Names
are the easiest to read in a macro (`"Scan"`), while rqids (`"i.skill.scan"`) also work in worlds
using another language.

If something can't be found, the API shows an error notification and stops the macro.

## Compatibility

The API follows the RQG system version. When a system update changes the API or moves or renames a
field in the character data in a way that can break macros or modules, the release notes say so.
Check them when updating the system.

### Deprecations

When the system replaces a method, a field or a syntax, the old one keeps working for a while. Using
it logs a deprecation warning in the browser console (press F12), once per session. The warning
names what to use instead, the version that deprecated it and the version that removes it, for
example _deprecated since Version RQG 6.2.0 / removed in Version RQG 6.4.0_.

- The old way stays for at least one minor version, usually two, before it is removed.
- The removal version is fixed when the deprecation is announced, and the release notes list it.
- Update your macros and modules while the warning is showing. After the removal version the old
  call stops working.
